Собери локальный визуальный редактор для личного UI-kit. Источник истины —
html-файлы на диске, никакой БД и отдельного формата проекта.

СТЕК: ванильный JS/TS. Приложение отдаётся локальным сервером (localhost),
НЕ открывается напрямую как file:// — это нужно для same-origin доступа
к вложенным iframe (см. ниже). Минимум зависимостей.

АРХИТЕКТУРА:

1. Viewport — div с pan (drag) и zoom (wheel/pinch) через
   CSS transform: scale() translate() на content-контейнере.
2. Frame — фиксированного размера div внутри viewport, куда парсится
   <body> открытого html-файла и рендерится как настоящий живой DOM.
3. Открытие/сохранение файла — либо File System Access API, либо через
   эндпоинт локального сервера на чтение/запись файла (проще и надёжнее,
   раз сервер всё равно есть). Правки идут напрямую в DOM внутри frame.

ИНСТРУМЕНТЫ ВСТАВКИ ЭЛЕМЕНТОВ (5 штук):

- div, span, text, img — вставка в document flow (клик по инструменту,
  клик внутри frame добавляет элемент в конец родителя/после выбранного).
  Reorder — перестановкой среди siblings, не координатами.
- .html — вставляет <iframe> фиксированного размера, src указывает на
  НОВЫЙ создаваемый html-файл (аналог Figma Frame). Внутри этого iframe
  повторяется вся та же логика редактирования (viewport pan/zoom не нужен
  внутри вложенного frame — он сам statичный блок внутри родителя, но
  выделение/стили/классы должны работать и туда).
- Каждый новый файл, созданный через .html, автоматически линкует общий
  styles.css через <link> — чтобы root CSS классы были видны во всех
  вложенных frame'ах, а не дублировались.

ПРАВАЯ ПАНЕЛЬ (для выбранного элемента, в любом файле/frame):

- Raw CSS editor: список свойство-значение, пишет напрямую в el.style.
- Class manager: список классов на элементе, добавить существующий/создать
  новый.
- Root CSS browser: список классов из общего styles.css с их свойствами.
  Если работаешь внутри вложенного .html-frame — показывает тот же общий
  файл, не свой локальный.

ЖЁСТКО НЕ ДЕЛАТЬ (v1):

- Никакого absolute positioning и свободного драга элементов по координатам.
- Никаких анимаций.
- Вложенность .html-frame ограничить одним уровнем (frame внутри frame
  внутри frame — не поддерживать, пока не понадобится реально).
- Theme-переменные, компоненты — отдельная итерация.

ПОРЯДОК РЕАЛИЗАЦИИ:

1. Локальный сервер, отдающий папку с файлами + сам редактор
2. Pan + zoom viewport, рендер frame из открытого файла
3. Инструмент "div" — вставка, выделение, reorder
4. span, text, img по той же схеме
5. Raw CSS editor + class manager для выбранного элемента
6. Root CSS browser
7. Инструмент .html — создание файла, вставка iframe, линковка styles.css,
   проверка что выделение/стили работают и внутри iframe (same-origin)
8. Сохранение обратно в файлы

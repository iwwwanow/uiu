# Свой генератор конфигов тем: пакет `packages/theme-gen`

Готовые генераторы не подходят. В base16/tinted-theming 16 фиксированных слотов и нет уровней −1…3 (overlay, modal). themer, matugen и wallust тоже не дают задать свою модель ролей. Поэтому пишем свой маленький генератор на bun. Он читает CSS-переменные палитры и ролей из `theme/` uiu (CSS — единственный источник правды, без JSON) и подставляет их в шаблоны на строках JS. Основные программы (nvim, ghostty, zellij, waybar) получают цвета из модели уровней. Для второстепенных (lazygit, fzf, bat, delta, btop) генератор дополнительно выдаёт base16 `scheme.yaml` и использует готовые шаблоны tinted-theming.

Генератор — отдельный пакет в `packages/` (имя рабочее — `theme-gen`). Он попадает в pnpm workspace автоматически через `packages/*` в `pnpm-workspace.yaml`. Запуск через скрипты корневого `package.json` (`theme:build`, `theme:test`), пакет вызывается через `pnpm --filter`. Конфиги пишутся в `iwwwanow_dotfiles/.config/...`, дальше stow.

Тестирование должно быть надёжным, на `bun test`:
- юнит-тесты разбора CSS и перевода OKLCH → hex на эталонных значениях (например, #e0e0e0 ↔ L≈0.91);
- инварианты: каждая роль разрешается в ступень, в шаблонах нет hex, соседние уровни различаются по ΔL не меньше порога;
- снапшоты сгенерированных конфигов;
- проверка, что каждый выход валиден для своей программы: `ghostty +validate-config`, загрузка nvim-темы в `nvim --headless` без ошибок, разбор KDL для zellij, CSS для waybar.

Визуальный регресс — через vhs, см. `docs/backlog/2026-10-30_terminal-themes-levels-oklch.md`.
